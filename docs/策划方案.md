# 《终端里的一生》— 个人电脑发展史 · 科普动画策划方案

> 交互式单文件网页动画 · 终端（Terminal）视觉风格 · 每代机型均有可旋转的 ASCII 3D 展示
> 本文件只做决策，不含最终代码。请从下面每组选项中挑一个（或组合），我再开工。

---

## 0. 一句话主题

> **一台从 1975 年活到 2026 年的机器，在终端里回忆自己的一生。**

- **视觉基调**：CRT 磷光屏 —— 字符是像素，光是余晖，噪声是年代感。
- **叙事载体**：终端（命令行 / 自检日志 / 滚屏 / 光标闪烁 / 打字机输出）。
- **核心视觉母题**：**ASCII 3D** —— 每代个人电脑都以字符点阵构成的三维实体出现，可旋转、可拆解、可合体。
- **科普落点**：每代都给出「它比上一代多了什么」+「它改变了什么」，而不是罗列参数。

## 1. 分镜结构：五个方案（选一个作为骨架）

### 方案 A ·《时间轴·十二镜》编年线性
最正统的线性编年史，一代一镜，节奏统一。

| 项 | 内容 |
|---|---|
| 结构 | 1975 → 2026，每代个人电脑一镜，共 12 镜 |
| 单镜模板 | 年份打字机打出 → 机型名大字 → **ASCII 3D 旋转展示** → 规格逐行打印 → 一句「它改变了什么」→ 整屏滚屏转场 |
| 时长 | 12 × 14s ≈ **2′50″** |
| 优点 | 最易做、信息最清楚、代码结构最干净（`MACHINES[]` 数据数组 + 一个通用渲染器，加机型=加一条数据） |
| 缺点 | 节奏均匀，容易变成「会动的 PPT」 |
| 适合 | 想先把「每代一个 ASCII 3D」这条主线做扎实 |

### 方案 B ·《POST 自检》启动日志驱动
整部片子 = **一台机器的一次开机自检（POST）**，历史在自检输出里逐行展开。

| 项 | 内容 |
|---|---|
| 结构 | 不是按年份切，而是按「自检项」切：`MEMORY TEST` / `CPU CHECK` / `VIDEO BIOS` / `DISK BOOT` … 每一代机器是自检的一个阶段 |
| 母题 | **3D 模型随自检逐步成形**：先只出现线框 → 再填充字符 → 再上色 → 最后通电发光 |
| 台词样例 | `MEMORY TEST: 000256 BYTES .......... OK` / `CPU: INTEL 8080 @ 2.000 MHz ... OK` / `BOOT SECTOR 1977-04-16 ... APPLE ][ ... READY.` |
| 时长 | 单镜 8–12s，共 16–18 镜 ≈ **3′30″** |
| 优点 | 终端味最足；「字符从无到有长成一台机器」是极有设计感的视觉母题 |
| 缺点 | 文本量大，需要精心写「自检台词」，写不好会闷 |
| 适合 | 想追求「一眼就是终端」的强风格 |

### 方案 C ·《剖面》爆炸拆解
每代机器「**整机 → 爆炸散开 → 镜头钻进关键部件 → 合体**」。

| 项 | 内容 |
|---|---|
| 结构 | 8 代 × 每代 2 镜（拆 / 装），共 16 镜 ≈ **4′** |
| 3D 含量 | 最高。键盘、主板、CPU 芯片、软驱、CRT 显像管、散热器都能单独飞出，并用 ASCII 引线 + 方框标注 |
| 优点 | 视觉最惊艳；ASCII 3D 不是噱头而是**叙事手段**（「拆开才知道进步在哪」） |
| 缺点 | 建模量最大，每台机器要 15–30 个零件块；标注排版难 |
| 适合 | 想要「技术感 / 硬核」而非「怀旧感」 |

### 方案 D ·《对决》双机对撞
每镜两台同时代死对头并排，中间打参数对比表；左右两套 ASCII 3D **反相旋转**。

| 镜 | 对决 |
|---|---|
| 1 | 1977 Apple II ⟷ 1977 Commodore PET |
| 2 | 1981 IBM PC 5150 ⟷ 1982 Commodore 64 |
| 3 | 1984 Macintosh 128K ⟷ 1984 IBM PC/AT |
| 4 | 1985 长城 0520C-H ⟷ 1986 Compaq Deskpro 386（东西方对照） |
| 5 | 1993 Pentium PC ⟷ 1998 iMac G3（性能 vs 设计） |
| 6 | 2008 MacBook Air ⟷ 2012 Raspberry Pi |
| 7 | 2020 Apple M1 ⟷ 2026 AI PC |

| 项 | 内容 |
|---|---|
| 时长 | 7 镜 × 25s ≈ **3′** |
| 优点 | 戏剧性最强 —— 「个人电脑史就是一部战争史」 |
| 缺点 | 机型覆盖减半（只有 14 台里的一半被单独讲） |
| 适合 | 想要辩论感、记忆点强 |

### 方案 E ·《混剪》主线 + 插入镜 ★ 推荐
时间轴为骨（A），终端启动日志为皮（B），在关键节点插入拆解（C）与对决（D）。

```
序幕   0:00–0:15   冷启动 · 黑屏 · 光标闪烁 · POST 自检开始
第一幕 0:15–0:55   萌芽 1975–1977   Altair 8800 → Apple II        [含 Altair 前面板开关拆解]
第二幕 0:55–1:50   标准 1981–1984   IBM PC 5150 → C64 → Mac 128K  [含 IBM PC 主板拆解 + PC vs Mac 对决]
第三幕 1:50–2:45   图形与网络 1985–1995  长城0520C-H → Compaq 386 → Windows 95 PC  [含 386 芯片拆解]
第四幕 2:45–3:40   便携与移动 1998–2012  iMac G3 → MacBook Air → iPad/Raspberry Pi
第五幕 3:40–4:20   片上系统 2020–2026    Apple M1 → AI PC
尾声   4:20–4:40   自检完成 · READY. · 屏幕熄暗只剩光标
```

| 项 | 内容 |
|---|---|
| 时长 | ≈ **4′40″**，14 台机型 + 3 次拆解 + 2 次对决 |
| 优点 | 节奏有起伏，信息最完整，ASCII 3D 的三种用法（展示 / 拆解 / 对决）都用上了 |
| 缺点 | 工作量最大，需分 3–4 批实现（可先做骨架 + 前 4 代给你看效果，再续） |

## 2. 单镜「分镜卡」规范（无论选哪个方案，每镜都要写清这 10 项）

| 字段 | 含义 | 示例 |
|---|---|---|
| `SHOT` | 镜号 / 时间码 / 时长 | `S07 · 01:52–02:08 · 16s` |
| `YEAR/SUBJECT` | 年份 + 机型中英文全称 | `1984 · Macintosh 128K · 麦金塔` |
| `FRAME` | 画面分栏（日志流 / 3D 区 / 字幕区比例） | `左 38% 日志流 · 右 62% 3D 区 · 底部 4 行字幕` |
| `MODEL` | 3D 零件块清单 + 面片量 | `机箱/主板/CPU/软驱/CRT/键盘/鼠标 = 7 组 23 块` |
| `CAM` | 镜头运动与角速度 | `轨道自转 18°/s + 缓慢俯仰 + 末段推近 1.6×` |
| `ASCII` | 字符网格分辨率 / 字符梯度集 / 是否描边 / 是否抖动 | `128×58 · " .:-=+*#%@" · 显式描边 · 误差扩散抖动` |
| `TONE` | 配色与辉光 | `琥珀单色 #ffb000 · 余晖 2 帧 · 扫描线 4px` |
| `COPY` | 逐行屏显文字 + 打字速度(cps) + 停留 | `38 cps · 每行停 0.4s` |
| `SFX` | 音效 / 转场 | `机械键盘咔哒 · 5.25″ 软驱读盘 · CRT 高压嗡鸣 · 滚屏` |
| `FACT` | 需可溯源的关键数字 | `68000 @ 7.8336 MHz · 128 KB RAM · $2495` |

> 这是「分镜要求」的骨架。要不要加 **旁白字幕**、要不要加 **年代背景条**（同期的世界大事），也算选项，见第 5 节。

## 3. ASCII 3D 渲染方案：三选一

### R1 · 纯软件光栅器 + 字符梯度（`donut.c` 流派，零依赖）
- 机型建模成**轴对齐方块集合** → 三角形 → 旋转矩阵 → 透视投影 → z-buffer → 按法线亮度映射到 `" .:-=~:;=!*#$@"`。
- 分辨率 ~110×46 字符网格，逐帧 30fps 在 canvas 上画字符。
- ✅ 真·终端味、零依赖、性能极好、字符密度完全可控
- ❌ 曲面难做（CRT 弧面、鼠标、圆角机身要靠大量小方块近似）；建模需手写

### R2 · three.js 离屏渲染 → 亮度/颜色量化 → 字符化 ★ 推荐
- 复用工作区里已有的 `libs/three.min.js`（r128 UMD，603KB）与 `libs/OrbitControls.js`。
- 真 3D 建模（`BoxGeometry` 拼机身 / `LatheGeometry` 做 CRT 弧面 / `TorusGeometry` 做软驱口），渲染到 **160×70 的 WebGLRenderTarget**，`readRenderTargetPixels` 读回像素 → 按亮度映射字符、按源像素给字符上色 → 画到 `<pre>`/canvas。
- ✅ 借 three.js 的光照/阴影/材质能力，模型真的像；爆炸拆解动画几乎免费（改 `position` 即可）
- ❌ 依赖 `libs/three.min.js`；需自己写「像素 → 字符 + 颜色」的量化层

### R3 · 混合双通道（R2 + 纯字符前景层）
- 3D 主体走 R2；**扫描线、CRT 桶形弯曲、字符抖动、光标、日志流、边框**全部用 DOM/CSS 字符层叠加。
- ✅ 层次最丰富，可以做辉光溢出、屏幕弯曲、偶发雪花噪点
- ❌ 复杂度最高

## 4. 机型清单：三条路线

### L1 · 世界主线（12 台）
`1975 Altair 8800` → `1977 Apple II` → `1981 IBM PC 5150` → `1982 Commodore 64` → `1984 Macintosh 128K` → `1986 Compaq Deskpro 386` → `1995 Windows 95 PC` → `1998 iMac G3` → `2008 MacBook Air` → `2010 iPad` / `2012 Raspberry Pi` → `2020 Apple M1 MacBook Air` → `2026 AI PC`

### L2 · 世界 + 中国线（16 台）★ 推荐（更贴合中文观众）
在 L1 基础上插入：
- `1985 长城 0520C-H`（国产微机代表，中文 DOS/CCDOS 生态）
- `1996 联想 奔腾机`（国产 PC 规模化）
- `2000 神舟电脑 / 蓝猫`（价格战，电脑进家庭）
- `2020 华为鲲鹏 / 统信 UOS`（自主生态）

### L3 · 极简 8 台（90 秒短片）
`Altair 8800` → `Apple II` → `IBM PC` → `Macintosh` → `iMac G3` → `MacBook Air` → `Raspberry Pi` → `M1`

## 6. 交付与验收

- **主交付**：`pc-history-terminal/index.html`（单文件，双击即播）。
- **验收点**：
  1. 每台机型都能看到一个**字符构成的三维实体**，且可旋转（不是贴图、不是 2D 图）。
  2. 至少一次**爆炸拆解**与一次**并排对决**（若选方案 E / C / D）。
  3. 全部关键数字与年份**可溯源**（在代码里以 `FACT` 注释标出来源）。
  4. 无外部网络依赖（three.js 走本地 `libs/`）。
  5. 1080p 下 30fps 稳定；首帧 < 1s。
